TCP — a reliable byte stream
============================

  phone                         device
    │ ── SYN ──────────────────▶ │   3-way handshake
    │ ◀───────────── SYN+ACK ─── │   (the OS does this)
    │ ── ACK ──────────────────▶ │
    │ ══ bytes in order, no loss ═│
    │ ── FIN ──────────────────▶ │   close

What TCP gives you
  • order: bytes arrive in the order sent
  • no loss: lost segments are re-sent
  • NO message borders: send "AB" + "CD",
    the other side may read "A", "BCD"

So every protocol on TCP must mark its own
frames:
  MQTT    → remaining-length field
  Modbus  → MBAP length field
  HTTP    → blank line + Content-Length
  console → newline

Knobs
  host:port   who to talk to
  TLS         encrypt + check server cert
  NoDelay     send small frames now (this app
              turns Nagle's batching off)

Gotchas
  • connect timeout ≠ device down: check the
    phone and device are on the same network
  • "connection refused" = host up, port closed
  • a silent dead peer is only noticed when
    you send → protocols add keep-alives
