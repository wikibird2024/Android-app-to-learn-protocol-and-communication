CoAP (RFC 7252) — REST for tiny devices, on UDP
===============================================

  4-byte header + token + options + payload
  ┌──┬──┬────┬────────┬───────────┐
  │Ver│T │TKL │ Code   │ Message ID│
  └──┴──┴────┴────────┴───────────┘
  Code c.dd: 0.01 GET 0.02 POST 0.03 PUT
             0.04 DELETE · 2.05 Content
             4.04 Not Found · 5.00 error

Types
  CON  confirmable: wants an ACK, resent if lost
  NON  fire and forget
  ACK  "got it" (may carry the response)
  RST  "I don't know this message"

Reliability (done by the client, not UDP)
  CON → no ACK in 2–3 s → resend, 4, 8, 16 s
  → give up after 4 resends

Two ways to answer
  piggybacked: ACK carries 2.05 + payload
  separate:    empty ACK now, CON response
               later (we ACK it)

Options are delta-encoded: each stores
"number − previous number", so they must be
sorted. Uri-Path (11) repeats per segment:
/sensors/temp → "sensors", "temp".

Observe (option 6): the server pushes every
change of a resource with the same token.

Try
  coap.me /.well-known/core lists resources
  (link format). Then GET /test with CON off
  and on, and compare the log.
